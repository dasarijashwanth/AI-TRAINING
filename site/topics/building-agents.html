Building Agents

Now we build. An agent is simpler than it sounds: a loop around a model, some tools, and a way to know if it is working. This page gives you the architecture and a small worked example you can run.

The architecture: loop, tools, evals

Every agent has three parts:

  1. The loop. Send the goal and history to the model, read its response. If it called a tool, run the tool and feed the result back in. Repeat until it gives a final answer or hits a step limit.
  2. The tools. The actions the agent can take, each with a name, description, and parameters (see Customizing Agents).
  3. The evals. A set of test tasks with expected outcomes, run regularly. Without evals you are flying blind; with them, every change is measurable.
Start here

Build the evals before the agent. A golden set of 10 to 30 example tasks with expected answers tells you whether each change helped. This is the single highest-leverage habit in agent engineering.

Worked example: a tiny Q&A agent

Here is a minimal agent in Python. It uses a mock model function so you can run it with zero API keys; swap in a real model call when you are ready.

import json

TOOLS = {
    "get_weather": lambda city: {"temp_c": 22, "condition": "sunny"}
    if city == "Miami" else {"temp_c": 5, "condition": "rainy"},
}

def mock_model(messages):
    """Pretend model: asks for weather when it sees a city."""
    last = messages[-1]["content"].lower()
    if "weather" in last and "tool_result" not in last:
        city = "Miami" if "miami" in last else "Boston"
        return {"tool": "get_weather", "args": {"city": city}}
    return {"answer": f"Done. Tool results seen: "
            + str([m for m in messages if m.get("tool_result")])}

def run_agent(goal, max_steps=5):
    messages = [{"role": "user", "content": goal}]
    for step in range(max_steps):
        out = mock_model(messages)
        if "answer" in out:
            return out["answer"]
        result = TOOLS[out["tool"]](**out["args"])
        messages.append({"role": "assistant",
                         "content": json.dumps(out)})
        messages.append({"role": "tool", "tool_result": result,
                         "content": f"{out['tool']} returned {result}"})
    return "Stopped: hit step limit."

print(run_agent("What is the weather in Miami?"))

Trace the loop: the goal goes in, the model requests the get_weather tool, we run it, the result goes back into the messages, and the model produces the final answer. A real agent replaces mock_model with an LLM call that can output tool requests, but the loop is identical.

Evals: the worked example continues

Give this agent a golden set:

golden = [
    {"goal": "What is the weather in Miami?",
     "expect_tool": "get_weather",
     "expect_in_answer": "sunny"},
    {"goal": "What is the weather in Boston?",
     "expect_tool": "get_weather",
     "expect_in_answer": "rainy"},
]

Score each run: did it call the right tool, and does the answer contain the expected fact? Track that score every time you change the system prompt or add a tool. When the score drops, you broke something. When it rises, the change earned its place.

Example

You add a second tool, get_forecast. The golden set still passes, so the new tool did not confuse the agent. Then you reword the system prompt and one case fails: the agent now calls the forecast tool for a current-weather question. The eval caught in seconds what users would have reported in days.

Cost-aware design

Every loop step costs tokens. Two habits keep agents affordable: cap max_steps so a confused agent cannot loop forever, and use a cheap model for simple steps (tool selection) and a strong model only for hard reasoning. Measure cost per task in your evals, not just accuracy, and you will spot the expensive patterns early.

Where to go from here

Grow this skeleton one piece at a time: real model calls, retrieval over your own documents (RAG), a confidence gate that escalates instead of guessing, and logging of every step. Each addition gets validated against the golden set. That is the whole discipline: loop, tools, evals, repeat.
