Coding with AI Agents

AI coding agents can write, test, and debug software alongside you. Used well, they make you faster. Used carelessly, they fill your repo with confident bugs. This page is the workflow that keeps you on the right side of that line.

The workflow: plan, generate, verify

Never start with "build me the feature." Start with a plan you could defend:

  1. You write the plan. What the feature does, the files it touches, the edge cases, how you will test it. A few bullet points is enough.
  2. The agent generates. Give it the plan plus repo context. Small tasks in one go; big tasks one file or one function at a time.
  3. You verify. Read the diff, run the tests, run the code. Every time. No exceptions.
Example

You need a CSV export endpoint. You write: "Add GET /export returning CSV of the transactions table. Files: app/main.py (route), app/export.py (new, CSV writer). Edge cases: empty table returns headers only; cap at 100k rows. Test: new tests/test_export.py checks headers, one row, and the cap." The agent writes the code. You read every line of the diff, run pytest, and curl the endpoint yourself before merging.

Review habits that catch AI mistakes

AI-generated code has a failure signature. Watch for it:

  • Invented APIs. The model may call library functions that do not exist. If a call looks unfamiliar, check the docs.
  • Silent error swallowing. Generated code loves bare except: pass. Replace with real error handling.
  • Missing edge cases. It handles the happy path beautifully and forgets empty inputs, nulls, and timeouts. Your plan's edge cases are the checklist.
  • Over-engineering. Ask for the simplest version first. Abstractions can come later, once the simple version works.
The 30-second review

For every AI-generated diff, ask: does it run, does it handle the edge cases in my plan, and can I explain each line? If you cannot explain a line, do not merge it.

What to delegate vs what to keep

Delegate: boilerplate, test scaffolding, docstrings, refactors with clear before/after behavior, and "write the boring version first" drafts. Keep: architecture decisions, security-sensitive code (auth, payments, crypto), and anything where you are learning. If you let the agent write code you do not understand in a domain you are studying, you are renting knowledge you will never own.

Tests are the contract

The single habit that makes AI coding safe: tests written from your plan, not from the generated code. Write the test first, or at least write the test expectations yourself, then let the agent implement until the tests pass. A green test suite you designed is proof the code does what you meant. A green suite the agent wrote to match its own code proves nothing.

Example

Before the agent writes the CSV export, you write test_export_empty_table_returns_headers_only. Now the agent has a target it cannot redefine. When the test passes, you have verified behavior, not just output.

Iterate in small loops

Long agent sessions drift. Keep tasks under 15 minutes of agent work, commit or checkpoint often, and start a fresh session for each new task with the relevant context pasted in. Small loops mean small mistakes, and small mistakes are cheap to fix.
